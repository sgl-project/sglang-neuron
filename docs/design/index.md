# Design

How the plugin serves a model on Trainium, from the launch to a step on the NeuronCores.

| Topic | What it covers |
| --- | --- |
| [The runtime](runtime.md) | The plugin's entry points and source pins, how a launch resolves and the serving policy, process start-up, the model host and its contract, compilation and the graph buckets, a step and device sampling, the program-switch fence, the KV cache and its allocator, and what a launch refuses. |
| [Parallelism](parallelism.md) | Tensor parallelism in each model family, vocabulary sharding and the device sampler, expert parallelism, the DP controller and `--dp-size` replicas, DP attention with the DP identity and its control fence, the process groups, how ranks map to NeuronCores, the layouts each model serves or refuses, and what a new model's graphs need. |
| [Async scheduling and execution](async-scheduling-and-execution.md) | SGLang's overlap schedule on the device: a step launched before the previous one finishes, the decode's tokens kept on the device by the token relay, the streams and the one readback per step, where the flow waits and how it stays correct, turning it off with `--disable-overlap-schedule`, and debugging it with the host and device traces. |
| [Disaggregated inference](disaggregated-inference.md) | Prefill and decode servers, each on one node, except a decode in a multi-node layout that its model declares (Kimi-K3's two-node decode); the served layouts put the prefill on one node and the decode servers on the other nodes: the request flow, the KV moved over NIXL and EFA in the Neuron page layout, the patched NIXL build both servers load, routing and sizing a layout, the prefill and decode schedulers with the DP-attention decode in lockstep, the failure and abort handling, the configuration of each role, the supported topologies, adding a model and the limitations. |
| [Decode context parallelism](decode-context-parallelism.md) | `--dcp-size` on the PD decodes of GPT-OSS and Kimi-K3, and on Kimi-K3's PD prefill: each pair or group of attention-TP ranks splits every sequence's KV by page, the layout and its virtual pages, the groups, the decode inputs and the kernel's merge across the group, the PD transfer by whole pages, the configuration, what it serves and refuses. |
| [Context parallelism](context-parallelism.md) | The KV token context-parallel layout a model declares (one block of every page per attention-TP rank, every KV head on every rank): the pools that hold it, the platform runtime's PD-prefill inputs and checks and a model's own CP decode, its PD hand-off, the scatter from a whole-page prefill into a CP decode (the layout frame and its refusals, the rank mapping, the bounded send and drain, the state owner), the host (L2) tier over CP pages, the traced CP helpers, and what is refused, `--attn-cp-size` among it. |
| [Pipeline parallelism](pipeline-parallelism.md) | GPT-OSS-120B's pipelined PD prefill, PD decode and aggregated server, and the pipelined PD prefills of GLM-5.2 and Kimi-K3: the stages and their layout, the stage build, the NIXL seam that moves each boundary HBM to HBM, SGLang's PD PP loops in the overlap order with the prefill's asynchronous last stage and the decode's sampled-token relay, the KV sent after each stage's forward, failed rooms held alike on every decode stage, the configuration and what a pipelined launch refuses. |
| [MLA and DSA pools](mla-dsa-pools.md) | The paged latent and DSA index-K pools of the MLA and DSA models (DeepSeek-V2 serves on the latent pool with `SGLANG_NEURON_MLA_POOL=paged`): their paged layout and CP blocks, the zero-page contract with its compiled fills, the buffers a model declares, the upstream pool kinds and what the pools refuse. |
| [Recurrent state](recurrent-state.md) | The recurrent-state framework of the GDN and KDA models (Qwen3.5, Kimi-K3): a model's state declaration, the state pool on SGLang's request table with its padding slot and sink, the slot operations a model's kernels provide or share (the compiled ones), checkpoints against the radix cache, a prefill chunk from a cached prefix on a paged pool, and the P/D state transfer. |
| [Megakernels](megakernel.md) | How a whole-model NKI kernel serves through upstream SGLang's `MegakernelSpec`: the megakernel host (built object, phase programs, pool layouts, the whole-step dispatch and the direct submit), compiling its kernel graphs (the modular flow over repeated segments, the NKI compile mode), the DP-attention cohort snapshot that picks each step's programs, and the platform seams the plugin adds to SGLang's megakernel binding. |
